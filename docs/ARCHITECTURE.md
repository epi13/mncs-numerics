# Architecture

`mncs-numerics` is two things that reinforce each other: a real
numerical library written in MNCS (the workload), and the adversarial
harness that executes it across backends (the pressure instrument).
The library exists so the pressures are discovered by building, not
by brainstorming; the harness exists so every claim about the library
is machine-checked on every backend.

## Layers

1. **Scalar primitives** (`src/numerics/scalar_int.mncs`,
   `scalar_float.mncs`) — total functions with explicit overflow,
   trap, and domain contracts. No dependencies.
2. **Sequence reductions** (`vec_int.mncs`, `vec_float_reduce.mncs`)
   — generic `N`-parameterized traversals over exact sequences and
   views. `vec_float_reduce` imports layer 1 (`sqrt_value`, `fabs`).
   Constructs nothing: the all-backend envelope.
3. **Sequence construction** (`vec_float_build.mncs`) — `replace`-based
   elementwise kernels returning new sequences. Narrower backend
   envelope (pressure P-001); split from layer 2 so one lowering bug
   cannot poison reductions on LLVM.
4. **Small matrices** (`mat_float_small.mncs`) — concrete 2x2/3x3 over
   flat row-major sequences. Literal construction: all backends.
5. **Generic matrix reductions** (`mat_float.mncs`) — `trace`,
   `frobenius`, `sum`, `max` over nested `[[f64; N]; M]`. No
   construction: all backends.
6. **Generic matrix construction** (`mat_float_build.mncs`) —
   seeded `matvec`/`matmul`/`transpose`/`diag` (pressures P-001,
   P-003). Narrow envelope; multi-parameter entry is named directly
   from the corpus with `type_arguments` (P-002 repaired; the
   in-language driver wrappers are retired).
7. **Algorithms** — `quadratic` (stable form), Neumaier summation,
   two-pass variance, Newton square root live inside their layers,
   not in a separate algorithms package: each is small enough to
   carry its own stability argument next to its code.
8. **Consumers** (`examples/`) — statistics, trapezoid integration,
   solve-and-verify, logistic trajectories. Each imports library
   modules through `use` and is executed by the harness: examples
   are integration tests, not documentation ornaments.

## Supporting structure

- `tests/corpora/*.json` — committed deterministic execution corpora
  (384 cases), generated by `scripts/gen_corpora.py` from an
  independent Python oracle. Committed files must match generator
  output byte-for-byte; the runner never edits them.
- `tests/drivers/*.mncs` — nullary property programs (fixed
  adversarial instances of universal claims). The former
  multi-parameter seeding wrappers retired with the P-002 repair:
  corpora now name `mat_float`/`mat_float_build` instantiations
  directly with `type_arguments`.
- `scripts/mncs_lib.py` — value encoders (exact float bits, canonical
  record/finite identities), corpus builder, experiment runner.
- `scripts/gen_corpora.py` — the oracle. Mirrors MNCS operation order
  exactly AND validates algorithmic quality (Newton residuals,
  quadratic residuals, libm agreement) so a shared transcription bug
  cannot hide behind self-agreement. Asserts fire at generation time,
  never as test retries.
- `scripts/run_tests.py` — executes every suite × backend, with a
  pinned refusal matrix (`expected_refusals`): a refusal the ledger
  predicts counts as CONFIRMED; any other non-pass FAILs. An
  unexpected pass on a refusal-pinned backend is flagged loudly (the
  pressure may be fixed).
- `scripts/bench.py` + `benches/bench.mncs` — steps + wall-clock per
  kernel per backend, gated on exact expected values first.
- `repros/P-*/` — minimal standalone reproducers for every pressure,
  runnable without the rest of the repository.
- `docs/LANGUAGE_PRESSURES.md` — the ledger (13 pressures).
- `docs/NUMERICAL_SEMANTICS.md` — the numerical contract.
- `docs/BENCHMARKS.md` — baseline numbers and what they mean.
- `docs/rfcs/0001-foundation.md` — the founding RFC (adversarial
  framing; this document extends it with the library framing).

## Design decisions

- **Self-contained, no upstream imports.** `src/numerics/*` imports
  only each other (plus nothing from `mncs-language/library`). A
  numerical foundation that drags a versioned stdlib behind it is
  harder for `mncs-geometry`/`mncs-signal`/`mncs-physics` to vendor;
  the few duplicated helpers (`min/max/clamp`) are labeled in-source.
- **No host-language numerics.** All numerical semantics live in
  `.mncs`. Python computes oracle values; Rust compiles them. Neither
  implements library behavior.
- **Enums over traps for foreseeable domain edges** (empty views,
  zero divisors, singular systems), **traps for genuine faults**
  (overflow, non-finite data, out-of-contract shapes). The boundary
  is documented per function.
- **Exact-bit corpora, tolerance APIs.** Committed cases assert bits;
  `approx*` exists for consumers. No committed case was ever widened
  to pass (the `l1` oracle bug caught during this run was fixed in
  the oracle, and the former `fneg(+0.0)` deviation was pinned +
  reported until the `neg(x)` intrinsic repaired it — never rounded
  away).
- **Module split follows construction vs reduction shape.** It was
  load-bearing on LLVM under P-001 (whole-artifact poisoning); since
  the repair it is file organization over a unified backend
  envelope (every suite runs on all five backends).

## What is deliberately absent

- No `fma`/emulated-FMA (would lie about rounding; P-012).
- No higher-order `map`/`fold` with closures (no language support;
  concrete kernels instead; P-013).
- No pivoting solvers, decompositions, FFTs, or special functions
  beyond `sin`/`cos`: foundations first, and each needs the language
  features (closures, wider generics) that v1 proves missing.
- No heap, no dynamic sizes: every bound is static (`N <= 1024`,
  two-level nesting, 1M work product). Benchmarks measure what fits.
- No strided or transposed VIEWS (zero-copy): `transpose_into` copies
  lane by lane, and a strided access pattern must be spelled with
  explicit index arithmetic (`reversed` shows the idiom). Views are
  contiguous spans; aliasing/borrowing questions for mutable views
  never arise because mutation is functional (`replace` returns a new
  sequence) — at the cost documented in P-001/P-014.
